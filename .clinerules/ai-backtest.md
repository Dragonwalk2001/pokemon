# 规则：AI 改动必须回测【强制】

任何会改变 bot 决策的改动（评分、拿球、保留、进化、弃球、平局随机打破等），都要先跑完规定的 40 局回测，再决定是否保留。

## 固定赛制

- 2 人对局。
- **10 个固定种子**：`1..=10`，永久不变，用于跨实验比较。
- **10 个增量种子**：每次新实验使用 10 个从未用过的种子。
  - 游标保存在 `backend/arena-seeds.txt`，由 `arena` 官方模式自动读取并递增。
  - 禁止手工重置、回退或挑选游标；该文件随仓库提交。
- 固定 + 增量 = 20 个种子；每个种子交换先后手各一局：候选先手 + 候选后手，共 40 局。
- 候选与基线共用同一规则引擎、同一 seed；只有 bot 策略不同。
- 同一 `(seed, 座位顺序)` 必须逐字节可复现。

在 `backend/` 下执行官方回测：

```bash
cargo run -p splendor-pokemon-cli -- arena \
  --candidate heuristic --baseline heuristic-v1 \
  --require 50
```

命令自动读取游标，使用 10 个固定种子 + 10 个增量种子；完整跑完后把游标推进 10。

调试可用 `--seeds N --seed-start M` 指定任意种子区间；调试模式不读写游标，结果不能作为改动依据。

## 判定

- 主指标：**得分率 =（胜 + 0.5 × 平）/ 40**，候选必须 ≥ 50%。
- 同时核对：整体胜-负-平、固定种子与增量种子的分项、候选/基线平均分、先手/后手分项、僵局数。
- 出现新僵局、runner 报错、超过 `MAX_BOT_STEPS`，直接判失败，不合并。
- 不允许挑种子、回退游标或只跑单边先后手。
- 只跑单 seed / 单座位 / 调试种子的结果只能用于调试，不能作为改动依据。

## 游标消耗

- 官方模式只要完整跑完 40 局（无论是否达到门槛、是否有僵局），就消耗该组增量种子并推进游标。
- 不得用同一组增量种子反复试跑不同候选；改动后应使用下一组新种子。
- 如果 runner 在对局中报错、未跑完，则不写游标；修复实现后可以重跑同一组种子。
- 同一候选、同一组种子的复现只能使用调试模式，不能作为新的官方结果。

## 基线

- `heuristic-v1` 是冻结的对照组，不随默认策略调整；日常只改默认的 `heuristic`。
- 需要更换基线时，先让新基线在同一赛制下完成一轮完整回测，再同步更新本文件与 `BotKind` 的取值。
